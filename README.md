# Vegan Grove mobile

The iOS and Android app for [Vegan Grove](https://vegangrove.org), a privacy-first vegan community and activism platform for Southern California. Expo SDK 57, expo-router, TypeScript, MapLibre. Read `SOUL.md` before changing anything.

## Run

The app uses native modules that are not in Expo Go (MapLibre), so you need a development build once, then Metro:

```bash
nvm use                       # Node 24 (.nvmrc)
npm ci
cp .env.example .env          # edit if you are pointing at a non-production API
npx eas-cli@latest build --profile development --platform ios   # or android
npx expo start --dev-client
```

Expo Go will not load the places map. Everything else works there for a quick look, but do not ship from it.

## Environment

| Name | Purpose |
|---|---|
| `EXPO_PUBLIC_API_BASE_URL` | API base including `/api`. Defaults to production in code. |
| `EAS_PROJECT_ID` | From `eas init`. Push tokens cannot be issued without it. |

`.env*` is gitignored except `.env.example`. Store profiles build with `EXPO_NO_DOTENV=1`, so a local `.env` can never leak into a store binary.

## Validate

```bash
npm run validate   # biome check + tsc --noEmit + scripts/check-prod-ready.sh
```

This is the CI contract. `check-prod-ready.sh` fails on `localhost`, private IPs, key prefixes (`sk_live`, `AKIA`, `AIza`), `EXPO_PUBLIC_USE_LOCAL`, a non-production URL in `.env.example`, or tracked `ios/`, `android/`, `.env`. Husky runs Biome on staged code and secretlint on every staged file.

## Layout

```
app/                 expo-router routes
  (auth)/            welcome, login, register, magic-link
  (tabs)/            index (Home), places, events, feed, messages
  profile/           index, edit, settings, privacy, account (hard delete)
  companion.tsx      Ivy, as a modal
src/
  constants/         api.ts (base URL + ENDPOINTS), areas.ts
  lib/api/           client.ts, auth, places, events, me, companion, types
  lib/stores/        authStore.ts (zustand)
  lib/notifications/ soft-ask + push token register/unregister
  lib/images/        stripExif.ts
  lib/query/         TanStack Query client
  theme/             tokens.ts (the --vg-* set), ThemeProvider.tsx
  components/        ui/, map/, composer/, notifications/
scripts/             check-prod-ready.sh, gen-brand-assets.mjs
```

`app.config.ts` is the only app config (no `app.json`). `ios/` and `android/` are generated by EAS and never committed.

## Release flow

EAS profiles in `eas.json` (all Node 24, `appVersionSource: remote`):

| Profile | Use |
|---|---|
| `development` | dev client, internal distribution |
| `preview` | internal build for testers |
| `production` | store-ready build, Android app bundle |
| `testflight` | store, iOS build number auto-increments, `EXPO_NO_DOTENV=1` |
| `playstore` | store, Android version code auto-increments, `NODE_ENV=production` |

```bash
npx eas-cli@latest build --profile testflight --platform ios
npx eas-cli@latest submit --profile testflight --platform ios
npx eas-cli@latest build --profile playstore --platform android
npx eas-cli@latest submit --profile playstore --platform android
```

`eas-build-pre-install.sh` runs the production checks on `testflight`, `playstore`, and `production`. Before the first submit, fill the `submit` block in `eas.json` (App Store Connect app id, Apple team id, Play service-account key path under the gitignored `secrets/`). OTA updates are intentionally unconfigured until a release policy exists.

## Privacy in this codebase

- Device location only moves the map camera. The API sees a bounding box.
- Every image is re-encoded through `stripExif` before it can be uploaded.
- Only the session token is persisted on device. The user record is refetched.
- No analytics SDK of any kind. No third-party fonts or icon CDNs.
